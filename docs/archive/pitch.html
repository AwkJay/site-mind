The problem

A $15B pipeline, checked one tired reviewer at a time

India is building roughly $15B of hyperscale data-centre capacity by 2027. The brief's own diagnosis names the two biggest causes of overrun: procurement misalignment and commissioning failures, both downstream of the same root cause: nobody has time to cross-check hundreds of clauses against a live schedule and a live supply chain, all at once, every time a drawing changes.

  • A single missed clause costs an estimated 20 engineer-hours and ₹15L in rework, a disclosed assumption, not a measurement, and stated as one on every screen that uses it
  • RFI-CIV-073 sat open for six days before a human caught a 30mm footing cover against a 50mm IS 456 minimum. SiteMind flags it the second the drawing uploads
  • By the time a non-conformance reaches site review, the concrete is often already poured

Why this isn't "another RAG chatbot"

We inverted the stack: retrieval and rules decide, the model only narrates

Most AI compliance tools ask a language model to both find the rule and judge against it, which is exactly how citations get invented. SiteMind never lets the model vote on pass/fail.

01
Extract
Parameter + its exact source sentence. Mandatory abstention on anything not confidently found.
→
02
Retrieve
The real, digitised IS/CEA clause that governs it, never paraphrased from model memory.
→
03
Decide
A deterministic Python threshold evaluated against that cited clause. Auditable. Reproducible.
→
04
Cite & act
NCR or ADVISORY, cited to the exact clause, with a source-reliability badge.
⤷
The LLM only writes prose, handed the decision after step 03 is already final. It narrates what the code proved. It never gets a vote.

A model that never decides can't quietly hallucinate a decision: that's the only reason a 0.0% hallucinated-citation rate is something we can measure and publish, not just claim.
